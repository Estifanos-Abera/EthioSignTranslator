# EthioSignTranslate
 
Open-source Ethiopian Sign Language (EthSL) recognition that runs in the browser.
 
A person signs a word in front of a webcam. The system recognizes the sign, shows the Amharic word, and builds sentences that can be read aloud. Recognition runs on the user's device. No video is uploaded and no account is needed.
 
**Live site:** ethiosigntranslate.vercel.app

## What it does
 
- **Translate:** live webcam recognition of isolated signs, a sentence strip, undo and clear, and speech output through the browser.
- **Research Mode:** shows the number of detected landmarks, prediction latency and the top three candidates for each sign.
- **Practice:** a list of the 15 signs with their Amharic words and glosses.
- **Contribute:** instructions for recording and submitting your own signs.
- **Docs:** the full build log, including the errors that came up and how each was fixed.
 
## Current status
 
This is the first version.
 
- 15 signs.
- Two signers contributed recordings.
- Test accuracy is 98 percent on a held-out split of 77 recordings. Both signers also appear in the training data, so this score measures recognition of people the model has already seen. Expect lower accuracy for new signers.
- The system recognizes isolated signs only. It does not translate continuous signing.
 
More signers and more signs are needed. See [Contributing](#contributing).

## How it works
 
```
Webcam -> MediaPipe hand landmarks -> features (30 frames x 252 values) -> GRU model -> sign
```
 
1. **Landmarks.** MediaPipe HandLandmarker finds 21 points on each hand in every frame.
2. **Features.** Positions are made relative to each wrist, velocity is added, and the sequence is resampled to 30 frames.
3. **Classification.** A two-layer GRU network predicts one of the 15 signs.
4. **Browser.** The model is converted to TensorFlow.js. The same feature code is written in both Python and TypeScript.
 
The Python feature code in `training/preprocess.py` and the TypeScript port in `webapp/lib/features.ts` must always match. If you change one, change the other.

## Quick start: run the web app
 
You only need this if you want to run or edit the website. The trained model and MediaPipe files are already in the repository.
 
**Requirements:** Node.js 20 or newer, and a webcam.
 
```bash
git clone https://github.com/Estifanos-Abera/EthioSignTranslator.git
cd EthioSignTranslator/webapp
npm install
npm run dev
```
 
Open the address printed in the terminal, usually `http://localhost:3000`, and go to `/translate`.
 
Run npm commands from inside the `webapp` folder, not from the repository root.
 
The browser only allows camera access on `https` pages or on `localhost`. Opening the dev server from another device by its network address will not work for the camera. Use the deployed site for that.
 
Check a production build before pushing:
 
```bash
npm run build
```
 
## Full pipeline: collect, train, convert
 
You need this to record data, retrain the model or reproduce results.
 
**Requirements:** Python 3.13 and a webcam. Python 3.14 is not supported by TensorFlow yet.
 
### 1. Set up the main environment
 
Windows (PowerShell), from the repository root:
 
```powershell
py -3.13 -m venv .venv
.venv\Scripts\activate
pip install -r training/requirements.txt
```
 
macOS or Linux:
 
```bash
python3.13 -m venv .venv
source .venv/bin/activate
pip install -r training/requirements.txt
```
 
### 2. Record data
 
```bash
python training/collect_data.py
```
 
The tool asks for your signer ID, shows the current sign in Amharic, and counts repetitions.
 
| Key | Action |
|---|---|
| Space | Start a repetition: 1.5 second countdown, then a 1.8 second recording |
| r | Delete the last repetition so you can record it again |
| n / p | Next or previous sign |
| q or Esc | Quit. Progress is saved and a session can be resumed |
 
Files are written to `data/raw/{signer_id}/{sign}/{signer_id}_{sign}_{rep:03d}.json`. After each repetition the tool prints how many frames contained a detected hand and warns when fewer than half did.
 
### 3. Preprocess
 
```bash
python training/preprocess.py
```
 
Writes `X.npy`, `y.npy`, `label_map.json` and `preprocessing_report.json` to `data/processed`. The report lists recordings that were excluded and why.
 
### 4. Train
 
```bash
python training/train.py
```
 
Trains on the CPU, saves the best model and the held-out test split to `models/trained`, and prints the test accuracy.
 
### 5. Evaluate
 
```bash
python training/evaluate.py
python training/visualize.py
```
 
`evaluate.py` writes a confusion matrix, training curves and a per-class report to `documents/project_docs/results`. `visualize.py` writes extra research figures to the `figures` folder inside it. It needs `pip install imageio`, and `--skip-loss-surface` skips the slow 3D loss surface.
 
### 6. Convert the model for the browser
 
Conversion needs its own Python 3.11 environment, because `tensorflowjs` requires TensorFlow 2.15, which does not support newer Python versions.
 
```powershell
py -3.11 -m venv .venv-convert-311
.venv-convert-311\Scripts\activate
pip install -r training/requirements-convert.txt
python training/convert_to_tfjs.py
python training/validate_to_tfjs.py
```
 
`convert_to_tfjs.py` rebuilds the network with `reset_after=False` on both GRU layers, loads the saved weights, checks them against the saved Python predictions, and writes the TensorFlow.js files to `webapp/public/model`. Both GRU layers in `train.py` must also use `reset_after=False`, because TensorFlow.js does not support the default setting.
 
After converting, restart the web app and test a few signs.
 
## Contributing
 
Contributions are welcome in three areas: recordings, model and pipeline changes, and the web app.
 
### Contribute recordings
 
More signers and more signs are the most useful contribution. Recording takes about an hour.
 
1. **Get a signer ID.** Open an issue titled "Signer ID request" so IDs do not collide. The current signers are `s1` and `s2`. Use the ID you are given.
2. **Set up** the main environment from the section above.
3. **Add your ID.** `training/class_list.py` lists the valid IDs in `VALID_SIGNER_IDS`. Add yours if it is not there.
4. **Prepare the room.**
   - Sit about an arm's length from a laptop webcam of 720p or better.
   - Light your face and hands from the front. Avoid a window behind you.
   - Keep both hands fully inside the frame, including during two-handed signs.
   - For two-handed signs, angle the camera slightly downward and keep one hand slightly offset from the other so neither hides it.
5. **Record.** Run `python training/collect_data.py`. Aim for 18 repetitions of each of the 15 signs, ideally in two sessions on different days. Raise your hand into the starting position during the countdown, perform the sign once, and hold the final pose until the recording ends. Press `r` to redo a repetition if you made a mistake, the hand left the frame, or the tool warns about low detection.
6. **Check.** Run `python training/preprocess.py` and read `preprocessing_report.json`. Redo recordings that were excluded.
7. **Submit.**
   - Create a branch and add only your folder, `data/raw/{your-id}/`.
   - Open a pull request. In the description, write your camera, the lighting and the room.
   - Do not add names, faces or video. The files contain hand landmark coordinates only.
 
By submitting recordings you agree that they will be published under CC BY 4.0 as part of the dataset. Only submit your own recordings, or recordings made with the clear consent of the signer.
 
If you are an EthSL signer and notice that a sign in the list is incorrect, or that the word order is wrong, please open an issue. Corrections from signers matter more than anything else here.
 
### Contribute code
 
1. Fork the repository and create a branch.
2. Make focused changes. Keep each pull request to one purpose.
3. If you change feature extraction, change `training/preprocess.py` and `webapp/lib/features.ts` together. Retrain, convert, and test live in the browser.
4. For web changes, run `npm run build` and `npm run lint` inside `webapp` and fix errors before opening the pull request.
5. In the pull request, describe what changed, why, and how you tested it. Include the test accuracy if the model changed.
 
### Report problems
 
Open an issue and include your operating system, browser, Python and Node versions, the exact command you ran, and the full error message. For accessibility problems, add the label `accessibility` and describe the assistive technology you used.
 
## Data format
 
Each repetition is one JSON file.
 
```json
{
  "signer_id": "s1",
  "class_label": "selam",
  "rep_num": 4,
  "timestamp": "UTC time of the recording",
  "fps": 30,
  "mediapipe_model": "hand_landmarker.task",
  "mediapipe_model_version": "1",
  "frames": [
    {
      "frame_idx": 0,
      "hand_1": {
        "handedness": "Right",
        "confidence": 0.98,
        "landmarks": [[0.51, 0.63, 0.0]]
      },
      "hand_2": null
    }
  ]
}
```
 
- `landmarks` holds 21 `[x, y, z]` triplets in normalized image coordinates. The example shows one.
- A hand that was not detected in a frame is `null`.
- `hand_1` and `hand_2` are only the order MediaPipe returned the hands in. The real left or right hand is in `handedness`.
- Recording frames are mirrored before detection, and the handedness label is swapped so that it matches the signer's real hand.
- Files are stored as recorded. All normalization happens in `preprocess.py`, so others can apply their own.
 
## Feature specification
 
- Each hand has 21 landmarks with 3 coordinates, which is 63 values.
- Each frame holds, in this order: left hand position, right hand position, left hand velocity, right hand velocity. That is 252 values.
- A sequence has 30 frames, so the model input has shape `(30, 252)`.
- Positions are relative to each hand's wrist. Velocity is the change from the previous frame, and it is zero for the first frame.
- A hand that is never detected stays at zero, which is normal for one-handed signs.
- Gaps of up to 5 frames are filled by linear interpolation. Edge gaps repeat the nearest detected frame. Longer gaps are set to zero.
- Recordings where a hand appears in some frames but fewer than half of them are excluded.
 
## Model
 
```
Input (30, 252)
Masking (mask value 0.0)
GRU 64 units, return sequences, reset_after=False
Dropout 0.3
GRU 32 units, reset_after=False
Dropout 0.3
Dense 32, ReLU
Dense 15, softmax
```
 
About 72,000 parameters. Adam optimizer with learning rate 0.001, batch size 32, early stopping on validation loss with patience 10. The data is split 70, 15 and 15 percent into train, validation and test, stratified by sign and pooled across signers.
 
## Troubleshooting
 
The Docs page of the site has a longer list with causes. The most common problems:
 
| Problem | Fix |
|---|---|
| `pip` cannot find TensorFlow | Use Python 3.10 to 3.13 for the main environment. Python 3.14 is not supported yet. |
| `tensorflow` and `tensorflowjs` conflict | Keep them in separate environments, as described above. |
| `GRUCell does not support reset_after` in the browser | Train and convert with `reset_after=False` on both GRU layers. |
| `Shape mismatch [192] vs [2,192]` | The model was trained with `reset_after=True`. Retrain with `False`, then convert again. |
| `WinError 4551 Application Control policy has blocked this file` | Windows or a security program blocked the MediaPipe library. Allow the project folder in the security program. |
| `Module not found: ./globals.css` | Make sure `webapp/app/globals.css` exists and restart `npm run dev`. |
| Next.js reports multiple lockfiles | Run npm only inside `webapp` and delete any `package-lock.json` at the repository root. |
| Camera does not open on another device | Browsers allow the camera only on `https` or `localhost`. Use the deployed site. |
| Page never loads on another device in development | Add that device's address to `allowedDevOrigins` in `webapp/next.config.ts`. |
| Speak is silent | Some devices have no Amharic voice installed. Try another browser or device. |
 
## Limitations
 
- Two signers in the training data. The model works best for people it has seen.
- 15 signs, which is a small part of the EthSL vocabulary.
- Isolated signs only. Continuous signing is not supported.
- A single camera cannot see a hand that is hidden behind the other hand. This can affect some two-handed signs.
- The first page load downloads several megabytes of model and library files.
- Sentence word order is unconfirmed with signers.
